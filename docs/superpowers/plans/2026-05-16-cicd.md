# CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GitHub Actions CI (lint + test + build on every push/PR) and CD (push Docker images to Docker Hub on merge to main).

**Architecture:** Two separate workflow files — `ci.yml` triggers on all branches/PRs, `cd.yml` triggers only on push to main. Branch protection on main ensures CD only runs on verified code. Docker images pushed to Docker Hub as `mimove/poc-airplanes-manager-backend:latest` and `mimove/poc-airplanes-manager-frontend:latest`.

**Tech Stack:** GitHub Actions, Docker Buildx, Docker Hub, uv (Python), Node 20, pytest, vitest, ruff.

### Task 1: Create CI workflow

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create the GitHub Actions directory**

```bash
mkdir -p .github/workflows
```

- [ ] **Step 2: Write the CI workflow**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: ["**"]
  pull_request:
    branches: [main]

jobs:
  backend:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ./backend
    steps:
      - uses: actions/checkout@v4

      - uses: astral-sh/setup-uv@v4

      - name: Install dependencies
        run: uv sync --frozen

      - name: Lint
        run: uv run ruff check app/ tests/

      - name: Format check
        run: uv run ruff format --check app/ tests/

      - name: Unit tests
        run: uv run pytest tests/unit/ -v

      - name: Integration tests
        run: uv run pytest tests/integration/ -v

  frontend:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ./frontend
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"
          cache-dependency-path: frontend/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Test
        run: npm run test

      - name: Build
        run: npm run build
```

- [ ] **Step 3: Commit and push to a feature branch**

```bash
git checkout -b feat/cicd
git add .github/workflows/ci.yml
git commit -m "ci: add CI workflow for backend and frontend"
git push -u origin feat/cicd
```

- [ ] **Step 4: Verify CI runs on GitHub**

Open `github.com/mimove/poc-airplanes-manager/actions` and confirm:
- Both `backend` and `frontend` jobs appear
- All steps pass (ruff, pytest unit, pytest integration, vitest, vite build)

If any step fails, fix the issue locally, commit, and push again. Common issues:
- `uv sync` fails: check `uv.lock` is committed
- Integration tests fail: testcontainers pulls `postgres:16-alpine` — first run is slow (~60s), not a failure
- `npm ci` fails: confirm `package-lock.json` is committed in `frontend/`

### Task 2: Create CD workflow

**Files:**
- Create: `.github/workflows/cd.yml`

- [ ] **Step 1: Write the CD workflow**

Create `.github/workflows/cd.yml`:

```yaml
name: CD

on:
  push:
    branches: [main]

jobs:
  build-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: docker/setup-buildx-action@v3

      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: Build and push backend
        uses: docker/build-push-action@v6
        with:
          context: ./backend
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/poc-airplanes-manager-backend:latest

      - name: Build and push frontend
        uses: docker/build-push-action@v6
        with:
          context: ./frontend
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/poc-airplanes-manager-frontend:latest
```

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/cd.yml
git commit -m "ci: add CD workflow to push images to Docker Hub"
git push
```

### Task 3: Configure GitHub secrets

**Note:** This task is performed in the GitHub web UI — no code changes.

- [ ] **Step 1: Create Docker Hub access token**

1. Go to `hub.docker.com` → Account Settings → Security → New Access Token
2. Name it `github-actions-poc-airplanes`
3. Permissions: Read, Write, Delete
4. Copy the token (shown only once)

- [ ] **Step 2: Add secrets to GitHub repo**

1. Go to `github.com/mimove/poc-airplanes-manager` → Settings → Secrets and variables → Actions
2. Add `DOCKERHUB_USERNAME` = `mimove`
3. Add `DOCKERHUB_TOKEN` = (token from Step 1)

### Task 4: Open PR, merge, verify CD

- [ ] **Step 1: Open pull request**

```bash
gh pr create --title "feat: add CI/CD workflows" --body "$(cat <<'EOF'
## Summary
- CI workflow: ruff lint+format, pytest unit+integration, vitest, vite build
- CD workflow: build and push backend+frontend Docker images to Docker Hub on merge to main

## Test plan
- [ ] CI jobs pass on this PR
- [ ] After merge, CD job runs and images appear on Docker Hub
EOF
)"
```

- [ ] **Step 2: Confirm CI passes on the PR**

Check `github.com/mimove/poc-airplanes-manager/actions` — both `backend` and `frontend` jobs must be green before merging.

- [ ] **Step 3: Merge the PR**

```bash
gh pr merge --squash --delete-branch
```

- [ ] **Step 4: Verify CD ran and images exist**

1. Check `github.com/mimove/poc-airplanes-manager/actions` — `CD` workflow triggered by the merge
2. Check `hub.docker.com/r/mimove/poc-airplanes-manager-backend` — `latest` tag present
3. Check `hub.docker.com/r/mimove/poc-airplanes-manager-frontend` — `latest` tag present

- [ ] **Step 5: (Optional) Enable branch protection on main**

1. Go to `github.com/mimove/poc-airplanes-manager` → Settings → Branches → Add branch protection rule
2. Branch name pattern: `main`
3. Enable: "Require status checks to pass before merging"
4. Add required checks: `backend`, `frontend`
5. Enable: "Require branches to be up to date before merging"
6. Save

This ensures future PRs cannot be merged if CI fails.
